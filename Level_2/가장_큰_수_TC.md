# 가장 큰 수 - 자체 테스트케이스

| # | 입력 | 기대 출력 | 실제 출력 | 결과 |
|---|------|-----------|-----------|------|
| 1 | [6, 10, 2] | "6210" | "6210" | Pass |
| 2 | [3, 30, 34, 5, 9] | "9534330" | "9534330" | Pass |
| 3 | [0] | "0" | "0" | Pass |
| 4 | [0, 0] | "0" | "0" | Pass |
| 5 | [0, 0, 0] | "0" | "0" | Pass |
| 6 | [1000, 1000] | "10001000" | "10001000" | Pass |
| 7 | [34, 34] | "3434" | "3434" | Pass |
| 8 | [0, 1000] | "10000" | "10000" | Pass |

- TC 1~2: 문제 예제
- TC 3: 배열 길이 1 (엣지 케이스)
- TC 4~5: 모든 원소가 0인 경우. 단순 이어붙이기로는 "00", "000"이 되어 앞자리 0 처리가 누락되는 회귀 테스트 케이스 (정답은 "0"이어야 함)
- TC 6: 자릿수가 큰 값(제한 최댓값 1000)의 중복 값 처리
- TC 7: 자릿수가 같은 중복 값 처리
- TC 8: 자릿수가 다른 두 값(0과 1000)을 이어붙였을 때, 단순 문자열 사전순 비교("0"+"1000"="01000" < "1000"+"0"="10000")와 결과가 갈리는지 확인하는 케이스 — a+b vs b+a 비교 방식이 올바르게 동작함을 검증

> 참고: 실행 환경에 C++ 컴파일러(cc1plus)가 설치되어 있지 않아, `solution` 함수와 동일한 로직(`to_string`으로 변환 후 `a+b > b+a` 비교자로 정렬, 앞자리가 '0'이면 "0"으로 처리)을 Python으로 이식하여 실제 출력을 검증했습니다. 추가로 원소 100,000개(각 999) 입력으로 정렬 성능(O(N log N))에 문제가 없음을 확인했습니다.
