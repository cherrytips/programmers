# 전화번호 목록 - 자체 테스트케이스

| # | 입력 | 기대 출력 | 실제 출력 | 결과 |
|---|------|-----------|-----------|------|
| 1 | ["119", "97674223", "1195524421"] | false | false | Pass |
| 2 | ["123", "456", "789"] | true | true | Pass |
| 3 | ["12", "123", "1235", "567", "88"] | false | false | Pass |
| 4 | ["119"] | true | true | Pass |
| 5 | ["1", "21"] | true | true | Pass |
| 6 | ["12", "34", "56"] | true | true | Pass |
| 7 | ["1", "10", "100"] | false | false | Pass |

- TC 1~3: 문제 예제
- TC 4: 배열 길이 1 (엣지 케이스)
- TC 5: 접두어 관계는 아니지만 부분 문자열로는 포함되는 경우. 기존 코드가 `find() != npos`(부분 문자열 검사)를 사용해 오답(false)을 반환하던 회귀 테스트 케이스
- TC 6: 모든 번호 길이가 같아 접두어 관계가 불가능한 경우
- TC 7: 3개 이상의 번호가 연쇄적으로 접두어 관계를 이루는 경우 (정렬 후 인접 비교만으로 충분한지 검증)

> 참고: 실행 환경에 C++ 컴파일러(cc1plus)가 설치되어 있지 않아, `solution` 함수와 동일한 로직(정렬 + 인접 원소 `find() == 0` 접두어 검사)을 Python으로 이식하여 실제 출력을 검증했습니다.
